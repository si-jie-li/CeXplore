# C. elegans Lineage Explorer Lite：开发与实现说明

本文面向“会用 Python 做数据分析，但不熟悉网页开发、npm、React、TypeScript”的读者。目标不是让你立刻成为前端工程师，而是让你能看懂这个工具由什么组成、各部分为什么存在、数据如何从文件流到谱系树和三维胚胎，以及以后应该到哪里修改功能。

---

## 1. 先用一句话理解这个工具

这是一个只在本机浏览器中运行的单页应用（single-page application）：浏览器读取一个或多个胚胎坐标表，在内存中建立 embryo/time/trajectory 索引和细胞谱系，然后用 WebGL 绘制单胚胎、多胚胎叠加或平均核位置，用 SVG 绘制谱系树，并由一个共享状态把所有视图、颜色和分组同步起来。

它没有服务器端数据库，也不会把上传的数据自动发送到网络。

可以把它类比成一个 Python 程序：

```text
CSV/TSV/XLSX
    ↓
pandas.read_csv() / read_excel()       ← 对应本项目的 loaders
    ↓
清洗、groupby(frame)、建立索引          ← 对应 frameIndex
    ↓
谱系关系表 + 递归查找                   ← 对应 lineage
    ↓
一个保存当前选择、颜色、时间点的对象     ← 对应 Zustand store
    ↓
matplotlib/plotly/napari 的多个联动视图  ← 对应 React + SVG + Three.js
```

区别在于：Python 脚本通常从头运行到尾，而浏览器应用一直运行，用户每点击一次或移动一次时间轴，只有受影响的界面部分被更新。

## 2. npm、Node.js、nvm、Vite 分别是什么

### 2.1 JavaScript 与 Node.js

JavaScript 原本主要运行在浏览器中。Node.js 是一个让 JavaScript 也能在终端中运行的环境。

Python 类比：

| 网页生态 | Python 类比 | 作用 |
|---|---|---|
| JavaScript/TypeScript | Python 语言 | 编写程序 |
| Node.js | Python 解释器 | 在终端运行构建工具 |
| `node --version` | `python --version` | 查看解释器版本 |

注意：最终打开工具时，三维视图实际运行在浏览器里；Node.js 主要负责开发阶段的依赖安装、代码检查和启动本地网页服务。

### 2.2 npm

npm 是 Node.js 生态的包管理器，相当于 Python 中的 `pip`，但同时也常用来运行项目命令。

```bash
npm install
```

类似：

```bash
pip install -r requirements.txt
```

它会读取 `package.json` 中声明的依赖，把所需包安装到项目的 `node_modules/` 目录，并按照 `package-lock.json` 锁定的版本保证可重复安装。

```bash
npm run dev
```

类似执行一个在 `pyproject.toml` 或 Makefile 中定义的快捷命令。这里它会启动 Vite 开发服务器。

### 2.3 nvm

nvm（Node Version Manager）用于安装和切换多个 Node.js 版本，可以类比为 `pyenv`。

项目中的 `.nvmrc` 写着 `22.14.0`，表示这个项目验证过的 Node.js 版本。执行：

```bash
nvm use
```

nvm 会读取 `.nvmrc` 并切换到对应版本。这不会改变项目的数据。

### 2.4 Vite

Vite 是开发服务器和生产构建工具，可以粗略类比为：

- 开发时的 Flask/Django 本地服务，加上自动刷新；
- 同时负责把 TypeScript、React、CSS 和资源打包成浏览器可读取的 HTML/JavaScript/CSS。

开发模式：

```bash
npm run dev
```

代码修改后，浏览器可快速刷新。

生产构建：

```bash
npm run build
```

Vite 会生成 `dist/`，里面是已经压缩打包的静态网页文件。

## 3. 为什么使用 React 和 TypeScript

### 3.1 React：用组件组织交互界面

React 把界面拆成小组件。例如：

- `Embryo3D` 只负责三维胚胎；
- `LineageTree` 只负责谱系树；
- `CellList` 只负责细胞列表；
- `PlaybackControls` 只负责播放。

组件更接近 Python 中“一个职责明确的类或函数”，而不是把所有代码写在一个大脚本中。

React 的核心思想是声明式渲染：程序描述“当前状态下界面应该是什么样”，状态变化后 React 计算需要更新的部分。例如：

```text
currentFrameIndex 从 84 变成 85
    ↓
读取 frame 85 的 observations
    ↓
更新三维实例矩阵、时间轴文字和谱系状态
```

不需要手动清除整个页面再重画。

### 3.2 TypeScript：带类型检查的 JavaScript

TypeScript 可以类比为使用 `mypy`、`dataclass` 和类型注解的 Python。它在构建前检查：

- 一个 observation 是否有 `cellId/x/y/z/step`；
- 一个函数需要字符串还是数字；
- 可选字段是否被错误地当作必填字段；
- 组件之间传递的数据形状是否一致。

浏览器最终执行的仍然是 JavaScript。TypeScript 的作用主要是提前发现错误，提高后续修改的可靠性。

## 4. 整体架构与数据流

```text
用户一次选择一个或多个文件
    ↓
检查文件头和少量样例行（inspectFile）
    ↓
每个文件依次确认列映射；扫描 embryo/sample column 的全部 ID
    ↓
用户勾选每个文件要导入的 embryo；流式解析并合并（loadMappedRows）
    ↓
按需从 union time grid 抽帧，并为缺测 embryo 保持上一完整帧（frameSampling）
    ↓
清洗、去重、坐标归一化、建立 frame/trajectory 索引
    ↓
canonical parent table + 用户 parent 列
    ↓
生成 LineageModel 和 SVG 树布局
    ↓
存入一个共享 Zustand store
    ↓
┌───────────┬─────────────┬──────────┬────────────┐
│ 三维胚胎   │ 谱系树       │ 细胞列表  │ Cell Groups│
└───────────┴─────────────┴──────────┴────────────┘
              全部读取同一个状态
```

共享状态是同步的关键。项目没有为三维视图和谱系树分别保存一份 selection；它们都读取 `state.selection`。

因此：

```text
在谱系树点击 ABpl
    ↓
store.selection = {ABpl}
    ↓
三维视图、谱系树、列表同时读到这个集合
    ↓
三处同时高亮
```

如果选择“Lineage”，则先通过 `getDescendants(ABpl)` 得到数据中实际存在的所有后代，再一次性写入同一个 selection 集合。

Cell groups 展开后的成员 checkbox 也直接读取和修改 `state.selection`，不维护局部 checked 集合。因此 tree → Cells list → group member list 是真正双向同步；`Remove selected` 删除的是当前 selection 与目标 group 成员的交集。

## 5. 文件读取和列映射的实现

### 5.1 为什么先检查文件、再真正读取

用户选中文件后，程序先读取文件开头的一小段，识别：

- 分隔符是逗号还是 Tab；
- 有哪些列；
- 前几十行的示例值；
- 是否可能有 `cell_name`、`time`、`A_pos` 等常见字段。

然后显示 Column Mapper。这样用户可以在完整解析之前纠正映射。

对于当前研究数据，自动建议为：

```text
Cell ID       → cell_name
AP coordinate → A_pos
LR coordinate → L_pos
VD coordinate → D_pos
Time          → time
Embryo column → embryo_id
Embryo IDs    → 扫描后显示所有 ID，用 checkbox 勾选一个或多个
```

### 5.2 CSV/TSV 为什么采用流式解析

`01_wt_truncated_axis_aligned.tsv` 有约 233 万行。如果像 `pandas.read_csv()` 一样一次性把所有列和所有胚胎放入浏览器内存，会浪费大量内存。

这里使用 Papa Parse 的分块/Worker 方式：

1. 先流式扫描 `embryo_id` 的不同取值并显示 checkbox；
2. 用户勾选要导入的 ID；
3. 文件再次按块解析，不匹配所选 embryo 的行立即丢弃；
4. 只保存需要的 ID、时间、坐标和可选 parent；
5. 解析工作放到 Web Worker，减少主界面卡顿。

它类似 Python 中：

```python
selected = {"ctr_emb1", "ctr_emb2"}
for chunk in pandas.read_csv(path, chunksize=100_000, sep="\t"):
    keep = chunk[chunk["embryo_id"].isin(selected)]
    retained.append(keep[needed_columns])
```

### 5.3 XLSX 为什么单独处理

浏览器中的 XLSX 解析器通常需要先读取整个工作簿。程序会：

1. 读取工作簿；
2. 列出所有 worksheet；
3. 让用户选择 sheet；
4. 再按列映射转换成同一种 observation 格式。

SheetJS 被动态加载：只有用户选择 Excel 文件时才下载/解析对应代码，普通 CSV/TSV 启动不承担这部分成本。

### 5.4 导入时的共享帧抽样

`ColumnMapper` 默认写入 `mapping.frameSampleCount = DEFAULT_FRAME_SAMPLE_COUNT`（当前为 185）；选择 `All` 时该字段为 `undefined`。多文件导入要求所有 source 使用相同设置。所有已选文件解析完成后，`FileLoader` 才对合并的 `RawMappedRow[]` 调用 `sampleRowsByFrame`，所以候选时间是所有 embryo 的 step 并集，而不是第一份文件或某一个 embryo 的时间轴。

抽样规则为：

1. 在有序 union steps 上按索引均匀选取目标数量，包含范围两端（只选 1 帧时取中点）；
2. 检查所有有效 cell ID 是否至少在某个精确抽中帧出现；若未覆盖，以 greedy set-cover 方式加入能覆盖最多缺失 cells 的原始帧，因此最终数量允许略大于请求值；
3. 对每个目标 step、每个 embryo，优先取 exact frame；没有 exact frame 时复制该 embryo 最近的上一完整 frame 并把 step 改成目标值；在该 embryo 首帧以前不生成 observation；
4. 把得到的 rows 传给 `buildDatasetFromRows`。因此 frame/embryo/trajectory indexes、lineage summary、Mean、projection、trails 和 metrics 全部建立在同一个抽样后数据集上。

这里是 zero-order hold，不是坐标线性插值；保持“完整 embryo frame”也意味着只要该 embryo 有一个更晚的真实帧，就不会让已经消失的旧 cell 永久残留。选择 `All` 时完全跳过这一步，保留原 exact rows。

### 5.5 数据清洗规则

- 空 cell ID：跳过并警告；
- AP/LR/VD 对应值不是有限数字：跳过并警告；
- Time 或 Frame 是必选播放坐标；该值无效时跳过并警告；
- Time/Frame 模式下同一个 embryo、cell、step 出现多次：保留最后一条有效记录并警告；
- Frame interval 必须是大于 0 的有限秒数；
- 某些帧没有某个细胞：允许；
- 未知细胞名：仍保留三维位置，只标记 lineage unresolved。

## 6. 时间、帧和索引如何工作

所有有效数据最后统一为：

```ts
Observation = {
  cellId,
  step,
  x, y, z,
  renderX, renderY, renderZ,
  parentId?
}
```

无论输入列叫 `time` 还是 `frame`，内部都把用于播放的原数值称为 `step`。同时保留 `temporalMode`，因此界面仍会正确显示 Time 或 Frame。

`frameValues` 是所有有效 `step` 去重后的升序列表，store 保存的 `currentFrameIndex` 是该列表的下标。因此：

- Time：所有数值相同的 time rows 进入同一 `frameIndex.get(time)`；即使文件行顺序混乱，播放仍按唯一 time 值升序前进。Lineage axis 把原 time 值解释为 minutes。
- Frame：播放和 observation 继续使用原 frame 号；`mapping.frameIntervalSeconds` 仅在 lineage 布局中把纵轴值换算为 `(frame × intervalSeconds) / 60` minutes。

程序预先建立三个重要索引：

```text
frameIndex:
  step → 该时间点的所有 observations

embryoIndex:
  embryoId → 该胚胎的所有 observations

trajectoryIndex:
  embryoId + cellId → 该胚胎中该细胞按时间排序的 observations
```

Python 类比：

```python
frame_index = {t: df[df.time == t] for t in times}
embryo_index = {e: rows for e, rows in df.groupby("embryo_id")}
trajectory_index = {
    (embryo, cell): rows.sort_values("time")
    for (embryo, cell), rows in df.groupby(["embryo_id", "cell_name"])
}
```

播放时不需要反复扫描完整数据，只需 `frameIndex.get(currentStep)`。Overlay 轨迹也不需要重新 groupby，只需用 `(embryoId, cellId)` 的 composite key 读取 `trajectoryIndex`。

播放本身不做坐标线性插值。All 模式的每一帧对应 exact source observations；Sample 模式的每个目标 step 来自全体 embryo 的原始 union time grid，但单个 embryo 在缺帧时可能使用最近上一完整 frame。母细胞和子细胞的出现/消失因此由最终工作数据集决定。

## 7. 坐标归一化原理

原始 AP/LR/VD 数值会完整保留，用于信息框显示。为保持数据层兼容和代码简洁，内部字段仍叫 `x/y/z`，分别固定对应 AP/LR/VD；三维绘制额外使用 `renderX/renderY/renderZ`。

设三轴范围为：

```text
spanX = maxX - minX
spanY = maxY - minY
spanZ = maxZ - minZ
largestSpan = max(spanX, spanY, spanZ)
scale = 16 / largestSpan
```

每个点先减去全局中心，再乘以同一个 scale：

```text
renderX = (x - centerX) × scale
renderY = (y - centerY) × scale
renderZ = (z - centerZ) × scale
```

关键是三轴使用同一个比例，而不是分别拉伸到相同范围。因此原始空间的长宽高比例不会被破坏。

Column Mapper、三维坐标轴和 Cell info 都标为 AP/LR/VD。程序不根据数值自动判断方向，也不会自动翻转正负号；这个生物学含义来自用户在导入时选择的列。给定文件应映射 `A_pos → AP`、`L_pos → LR`、`D_pos → VD`。

## 8. 谱系解析为什么不能直接删除最后一个字母

对很多晚期标准命名，子细胞名称看起来像是在母细胞名称后附加 `a/p/l/r/d/v`。但早期谱系存在明显例外，例如：

```text
P0 → AB + P1
P1 → EMS + P2
EMS → MS + E
P2 → C + P3
P3 → D + P4
P4 → Z2 + Z3
```

因此程序从项目内置的 `src/lineage/data/complete_embryo_lineage_list.csv` 读取明确的 `cell_name → parent` 表，而不是删除末尾字符猜 parent。

解析顺序是：

1. 如果用户映射了 parent 列并提供了值，使用用户值；
2. 否则查 canonical parent table；
3. 沿 parent 不断向上，补齐连接数据中细胞所必需的祖先；
4. 如果找不到 parent，该细胞成为 unresolved root；
5. unresolved cell 继续出现在三维和列表中，不导致程序崩溃。

早期 P lineage 的关系还在代码中显式保留了一份可读 safeguard，防止以后更换 canonical 文件时破坏这些关键关系。

### 后代选择

`getDescendants(cellId)` 使用栈进行图遍历：

```text
把起始细胞放入 stack
while stack 非空:
    取出一个细胞
    如果它在数据中 represented，则加入结果
    把它的 children 加入 stack
```

返回的是显式 cell ID 列表。保存 group 时存的也是这些 ID，而不是只存“ABpl lineage”规则，所以分组可以复现。

## 9. 谱系树如何绘制

谱系树使用浏览器原生 SVG。每个细胞是一条从出生到分裂或最后观测时间的竖直 `<line>`；分裂时用水平 `<line>` 连接 daughters；名字是 `<text>`。这种画法与经典 C. elegans lineage diagram 一致：时间向下增加，横向主要表达谱系分支而不是空间位置。

布局分两部分：

### 横向位置

- 末端叶节点按 canonical table 的顺序排列；
- 内部细胞放在 daughters 横坐标的平均位置；
- 未知细胞排到独立 root。

### 纵向位置

- Time：细胞出生与分裂高度使用上传的 time，单位标为 minutes；
- Frame：使用 `(frame × frameIntervalSeconds) / 60`，纵轴标为 elapsed minutes；
- 连接祖先没有观测时，不伪造早于数据的 step，而是收拢到它的最早 observed descendant；
- y 轴 `minValue` 等于最早 branch value，不再强制向 0 取整；因此从 2-cell/4-cell 等阶段开始的数据不会在树顶端出现虚构空白时段；
- 单点出现的 terminal cell 至少延伸一个观测步长，保证 branch 可见和可点击。

母细胞的竖线终止于最早 daughter 的出生高度，同一位置绘制水平分裂线，daughter 再从该高度向下延伸。前 6 个层级（depth 0–5）的名字常驻显示；更晚细胞只在鼠标悬停 branch 时显示名字，避免数百个标签遮挡。

D3 Zoom 只负责把 SVG 内容整体平移和缩放。谱系拓扑与布局由本项目代码维护，因此以后可以替换更精确的时间算法，而不影响交互。

当前帧状态由每个细胞的 `firstStep` 和 `lastStep` 判断：

- `currentStep < firstStep`：future；
- `firstStep ≤ currentStep ≤ lastStep`：current；
- `currentStep > lastStep`：past。

整棵树不被隐藏，只通过透明度和虚线保留时间上下文。

## 10. 三维胚胎如何绘制

### 10.1 Three.js 与 WebGL

Three.js 是对 WebGL 的高级封装。WebGL 使用 GPU 绘制三维图形，可以类比为 Python 中的 OpenGL/VisPy，但直接运行在浏览器里。

React Three Fiber 让 Three.js 对象可以作为 React 组件组织。Drei 提供 OrbitControls、三维线条和 HTML 标签等常用工具。

### 10.2 为什么使用 InstancedMesh

如果每个细胞核都是一个单独的 Three.js sphere，几百个对象会产生较多 draw calls。项目使用 InstancedMesh：

- 球面几何只保存一份；
- 每个细胞只提供位置矩阵、缩放和颜色；
- GPU 一次批量绘制许多同形状细胞核；
- 帧变化时复用 mesh，只更新 instance buffer。

为了支持不同透明度，当前帧细胞被分为两个 instanced mesh：

- 明亮/选中/着色细胞；
- 灰色或淡化背景细胞。

这比为每个细胞创建独立材质更轻量。

### 10.3 相机交互

OrbitControls 提供：

- 左键拖动：旋转；
- 右键拖动：平移；
- 滚轮：缩放；
- damping：松手后平滑减速；
- Reset：回到固定初始位置；
- Focus：计算当前帧选中细胞的中心并移动相机 target；
- Angle：输入 azimuth/elevation/roll 或选择 ±AP/±LR/±VD preset，围绕当前 target 重算 camera offset 和 up-vector，保留当前 target 和 camera distance。

`cameraOffsetFromAngles` 使用 LR/Y 为基准 up axis：azimuth 0° 对应 +VD/Z，90° 对应 +AP/X；elevation 相对 AP–VD 平面并限制到 ±89.9°。`cameraUpFromAngles` 把基准 up 投影到视线法平面，再绕 viewing direction 旋转 roll；接近 ±LR 极点时改用 VD/Z 作为稳定参考。相机命令仍是带递增 `nonce` 的 `reset | focus | angle` discriminated union。

点击一个 instance 时，Three.js 返回 `instanceId`。程序用它找到对应 observation，然后更新共享 selection，所以列表和树也会同步。

## 11. 颜色、分组和显示模式

每个保存的 group 包含：

```ts
{
  id,
  name,
  color,
  cellIds: string[],
  visible,
  source,       // manual、cell、lineage 或 group
  rootCell?,
  createdAt
}
```

颜色显示逻辑集中在 `cellAppearance.ts`，而不是分别写在树、列表和三维组件中。这样同一个细胞在所有视图中使用相同规则。

### Color groups

- 所有细胞可见；
- 着色细胞使用组颜色；
- 其他细胞为灰色。

### Highlight

- 组细胞或当前 selection 明亮不透明；
- 其他细胞仍可见但明显淡化。

### Isolate

- 只显示 visible groups；
- 如果还没有 group，则可显示当前 selection；
- 多个 visible groups 可以同时存在。

一个细胞属于多个可见组时，最近创建的可见组颜色优先。隐藏一个 group 后，如果该细胞还属于另一个可见组，它仍然可见。

新建或改色时，同色被视为同一个逻辑 group：`applyColor` 和 `setGroupColor` 会合并成员，并同步重定向显式 Trails group filter。`addCellsToGroup` 把当前 selection 并入指定组；`removeCellsFromGroup` 支持成员级删除，且 lineage group 一旦被手工删减就转成 manual，避免动态 membership 再补回被删成员。

## 12. 轨迹如何实现

有 saved groups 时，轨迹目标来自 `settings.trailGroupIds`，默认 `'all'`；因此清空 live selection 不会删除 group trails。没有 saved group 时才回退到当前 selection。

范围模式为 `all | previous | custom`。`previous` 从有序 `frameValues` 按索引截取包含当前帧的最后 N 个实际帧，因而不连续 frame 编号也不会造成错误窗口。

`trailProgressAtStep` 先把当前 trail window 映射到 0–1；`trailVertexColor` 再同时编码三种视觉信号：alpha 由 `0.04` 非线性增加到 `1`，颜色由高明度/低饱和过渡到较深/高饱和。`Embryo3D` 把结果作为 RGBA `vertexColors` 交给同一个 Drei `Line`，由 GPU 沿线段插值。`settings.trailWidth` 提供 0.5–4 px 的统一线宽调节，默认 1.1 px。没有为了宽度渐变而把每两个时间点拆成独立 React line object，从而控制大量 cell trails 时的 draw-call 数量。

程序先合并被选 trail groups 的 explicit cell IDs，再从 `trajectoryIndex` 取出每个目标细胞的历史 observation：

1. 删除晚于当前 step 的位置；
2. `resolveTrailStepRange` 默认返回从首个 frame 到当前 step 的 all-previous 范围；previous 模式按实际 frame 索引取最后 N 帧；custom 模式把 start/end 规范化并吸附到实际 `frameValues`；
3. custom end 晚于当前 step 时只画到当前 step；当前 step 早于 custom start 时不画，避免显示未来位置；
4. 把归一化位置连接成细线；
5. 使用该细胞或 group 的颜色。

此外，`getDivisionConnections` 根据 lineage parent map 检查目标 cells。如果 mother 和 child 都属于本次 trail targets，就在同一个 embryo 内把 mother 的最后观测连接到 child 的首次观测；两个 daughters 会得到两条独立连接。Mean 模式在 mean positions 上做同样连接。除导入抽样或显式开启 Mean hold-last 所定义的 zero-order hold 外，它不生成中间坐标，也不把目标 group 外的 parent/child 强行接入。

`TrailProjectionPanel` 与 Group analysis 都是 workspace 左列 overlay drawer。收起态为左侧中部上下错开的 36 px 图标，仅用 `title` 提示名称；展开态固定 `grid-column: 1; grid-row: 1 / -1`、宽高 100%，只覆盖 lineage/list 两行，不进入右侧 Spatial view。窄列内两者的原横向内容改为纵向可滚动布局。

投影 drawer 复用 Trails range、active embryos 和 Overlay/Mean frame observations。默认模式下，`calculateGroupProjectedPosition` 对每个 group/step 求所有当前成员 observations 的 raw-coordinate centroid，并直接输出 centroid 的 AP/LR/VD 坐标，不再减去首个 centroid。Individual-cell 模式则为每个 explicit group member 单独调用同一函数；Overlay 有多个 embryo 时，这等价于先求同名 cell 的跨 displayed-embryo mean。组件从 lineage parent map 找出组内 parent/child，以 parent 最后一点到 child 第一点的直线画 mother→daughter fork。晚出现的 group/cell 从第一个真实坐标点开始，不在 Trails range 起点插入人为零点。

Axis mode 分为 Multiple 和 Single：Multiple 中 AP 为 solid、LR 为带 round linecap 的 dotted、VD 为 long dash；Single 用 radio 选一个轴，所有曲线和 division connectors 强制 solid。SVG y domain 直接取当前坐标最小/最大值；只有坐标范围实际跨过 0 时才显示零线。每条可见 path 上叠加一条透明宽 hit path，hover 时只在该 series 内寻找最近时间点，所以不需要为 cells × frames × axes 创建大量 circle DOM；tooltip 显示 cell/group、elapsed x 和 exact axis coordinate。Pointer drag 把矩形反解为新的 x/y domain，wheel 围绕 cursor 同时缩放两轴，clipPath 裁剪范围外曲线，Reset 清除 local zoom。

`projectionSeriesToCsv` 是独立纯函数，输出当前 group/cell series 与 selected axes 的原 step、elapsed、axis position 和 sample count；组件只负责创建 Blob 下载。Zoom 是显示范围，不会破坏或重算 underlying curves，CSV 导出当前已选择的完整 Trails-range curves。

### 12.1 Mean position Worker cache

第一次切换到 Mean position 时，`explorerStore.prepareMeanPositions` 启动 `meanPosition.worker.ts`。Worker 对当前 active embryos 的全部 observations做一次聚合，同时生成序列化的 `frameEntries` 和 `trajectoryEntries`；主线程只把它们恢复为两个 `Map`：

```text
mean frameIndex:      step → mean observations
mean trajectoryIndex: cellId → 按 step 排序的 mean observations
```

因此当前帧 nuclei、CellInfo、Mean trails 和 Mean division connections 都是索引读取与范围过滤，不再在播放时重新计算平均值。若导入选择 All，request 可设置 `holdLastFrame`：Worker 遍历 union `frameValues`，每个目标 step 对每个 embryo 使用 exact frame 或最近上一完整 frame；尚未开始的 embryo 不参与。关闭该选项则保持 exact-only。抽样导入已经固化了 hold-last rows，所以不再显示第二次选择。

缓存 key 包含排序后的 active embryo IDs 和 `exact/hold` 模式；embryo list 或缺帧模式改变时先取消进行中的 Worker、清除旧 Map，再自动启动新任务。切回 Overlay 不清缓存，切回 Mean 可立即复用；关闭 dataset、替换 dataset 或导入会改变 active embryos 的 Session 时会清理/重建。缓存是 derived data，不写入 Session JSON。

## 13. Session JSON 是什么

Session 文件只保存轻量配置：

- 原始文件名；
- column mapping；
- cell colors；
- groups 及其显式 cell IDs；
- group 名称和可见性；
- display settings。

它不复制原始数据，所以文件很小，但恢复时必须先加载原数据，再导入 Session JSON。

这种设计类似保存 matplotlib 的绘图参数和 selection，而不是把整个 DataFrame 再保存一次。

Cell groups tab 另有更窄、更适合人工阅读和跨 Session 复用的 `cexplore-group-list` JSON。其 v1 schema 只导出 dataset、exportedAt 和每组的 name/color/cells/visible/source/rootCell，不导出内部 id/createdAt/settings。导入时校验 format/version/颜色/cell 数组，按当前 dataset 的 cell 名过滤，并按颜色并入现有 group。

## 14. 性能设计

当前版本针对“一个或少量已配准胚胎、每个胚胎几百细胞、几百时间点”：

- CSV/TSV 流式解析并按 embryo 过滤；
- 只保留必要列；
- 多 embryo 保留行使用循环追加，避免 `push(...rows)` 在约 10 万行时触发浏览器函数参数/调用栈上限；
- 合并后立即释放 parser 返回数组的重复引用；Sample 完成后在建立 dataset 索引前释放原始累积行；
- 默认把所有 imported embryos 的 union time grid 均匀压缩到 185 个目标帧，仅为完整 cell coverage 增加必要帧，并在这些帧上对缺测 embryo 做上一完整帧保持；选择 All 可关闭；
- 提前建立 `frameIndex`、`embryoIndex` 和 `trajectoryIndex`；
- 谱系拓扑和布局用 `useMemo` 缓存；
- 三维使用 InstancedMesh；
- 帧变化更新 instance matrix/color buffer；
- Mean position 在独立 Worker 中预计算全部 frame/cell 平均值，并缓存 frame/trajectory 两个索引；播放过程不再扫描全部 observations；
- 不做坐标线性插值；抽样和可选 Mean 缺帧模式只做上一完整帧保持；
- 超过 160 个当前细胞时，标签只显示 selection，避免创建过多 DOM 标签；
- XLSX 解析器动态加载。
- group metric 只有点击 Run analysis 后才建立 kNN graph；只复制当前勾选 embryo 的必要字段到独立 Web Worker；
- kNN 查找针对很小的 k 使用固定长度 nearest list，避免给每个 nucleus 对全部距离完整排序；
- null comparison 重用同一 embryo/time 的 kNN graph，不为每个随机 group 重建空间图。

给定 `ctr_emb1` 的验证结果是：

```text
20,926 observations
722 unique cells
185 time points
最多 362 nuclei/frame
0 unresolved cells
0 import warnings
```

## 15. 错误处理与安全边界

导入时错误不会静默消失：解析/抽样/建索引异常会显示在当前 Column Mapper 内；无效行、重复 cell/time 行和 sampling coverage 会显示 warning，unresolved cell 显示 badge。Import warning strip 有本地 dismissed 状态和 × 按钮；dataset object 改变时重置，保证下一次导入的新提示仍出现。

数据只在浏览器内存中处理。项目没有上传 API、数据库连接或用户账号系统。Session 导出通过浏览器生成本地 JSON 下载。

需要注意：

- 浏览器刷新会清空尚未导出的 group/config；
- Session 不含原数据；
- XLSX 必须整体读入内存，因此超大表优先转换为 TSV；
- 当前版本不做访问控制或文件加密，本机其他能访问文件的人仍可读取源文件和导出的 Session。

## 19. 当前定量指标如何分层实现

当前实现没有把计算写进 `Embryo3D.tsx`，而是保持三层：

1. `src/analysis/groupMembership.ts` 与 `groupMetrics.ts` 是不依赖 React 的纯函数；
2. `runAnalysis.ts` 只负责逐 embryo/time 编排和 null；
3. `analysis.worker.ts` 把 CPU 计算移出界面线程；
4. `AnalysisPanel.tsx` 只准备当前用户选择、启动任务和显示结果；
5. `resultUtils.ts` 把结果转换为 cohort summary 或 CSV。

运行时数据流：

```text
当前 selection/saved group + displayed embryo IDs + checked metrics
    ↓ 用户点击 Run analysis
从 embryoIndex 只取选中胚胎的 cellId/time/AP/LR/VD
    ↓ structured clone 到 Web Worker
每 embryo × time：dynamic membership → one kNN graph → observed + matched null
    ↓
Analysis result rows → SVG cohort trends / embryo table / CSV
```

切换 playback 只移动结果图的 current-time marker，并读取已经算好的对应 row，不触发重算。改变 group、embryo 或参数也只把结果标为 stale，仍需用户主动点击 Run。

完整公式和统计解释见 `docs/群体空间指标.md`。后续增加 velocity correlation、persistent cohesion 或 symmetry metrics 时，应继续给 `AnalysisMetric` 增加独立纯函数和 synthetic test，而不修改 3D renderer。

## 20. 当前版本明确没有实现什么

- 胚胎 registration；
- variability/uncertainty envelope 和经过 registration 的 consensus embryo（当前 Mean 只是对已对齐输入逐 cell 求算术平均）；
- 细胞表面、显微图像、体渲染；
- 位置插值；
- lineage-persistent null、正式显著性检验和多重比较校正（当前 null 是每个 time 的局部 size/region matched exploratory control）；
- velocity correlation、persistent cohesion 和 symmetry-cause 指标；
- 自定义谱系编辑；
- 云端保存或多人共享；
- 自动生物轴解释；
- 大规模服务端数据库。

这些是有意留到未来的范围，不是当前代码遗漏。
